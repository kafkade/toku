# toku-apple

Native Apple apps for Toku, built with SwiftUI and the Rust FFI layer.

- **macOS app** — full-featured desktop app with sidebar navigation, sortable
  table, cover grid, statistics dashboard, and Goodreads CSV import.
- **iOS app** — iPhone and iPad app with touch-optimized library grid, barcode
  scanner, quick progress updates, and adaptive navigation.
- **watchOS app** — a wrist-first companion (`TokuWatch`) for glanceable reading
  tracking: currently-reading list, Digital Crown progress logging, quick status
  actions, glance stats, and a watch-face complication.

Both apps share the **TokuKit** Swift package for FFI, models, and view models.

## Architecture

```text
SwiftUI Views → Swift ViewModels → TokuFFI wrapper → toku-ffi (C ABI) → toku-core / toku-db
```

### Components

| Component | Description |
|---|---|
| `TokuKit/` | Swift Package with FFI wrapper, models, ViewModels, and shared UI components |
| `Toku/` | macOS SwiftUI app target |
| `TokuiOS/` | iOS SwiftUI app target (iPhone + iPad) |
| `TokuWatch/` | watchOS SwiftUI companion app target |
| `TokuWatchComplication/` | WidgetKit extension for watch-face complications |
| `TokuWatchShared/` | Snapshot model shared between the watch app and complication |
| `TokuKit/Sources/CTokuFFI/` | C module map pointing to the `toku.h` header |
| `TokuKit/Sources/TokuKitUI/` | Shared SwiftUI components (StarRatingView, FlowLayout, etc.) |

## Prerequisites

### macOS app

- macOS 14 (Sonoma) or later
- Xcode 15.4 or later
- Rust toolchain (`rustup` with `aarch64-apple-darwin` target)

### iOS app

- iOS 17.0 or later
- Xcode 15.4 or later
- Rust toolchain with iOS targets:

  ```bash
  rustup target add aarch64-apple-ios         # Device
  rustup target add aarch64-apple-ios-sim     # Apple Silicon simulator
  ```

### watchOS app

- watchOS 11.0 or later
- Xcode 16 or later (the `TokuWatch` scheme is generated by XcodeGen)
- Rust toolchain with watchOS targets:

  ```bash
  rustup target add aarch64-apple-watchos      # Device
  rustup target add aarch64-apple-watchos-sim  # Apple Silicon simulator
  ```

  The companion app keeps its own local FFI database and syncs through the
  existing op-log (same model as the iPhone app), so it builds and runs on a
  watch simulator without a paired phone. Live complication data additionally
  requires an App Group (`group.com.kafkade.toku`) provisioned with a signing
  team on the watch app and complication targets; without it the complication
  falls back to a placeholder.

## Build steps

### 1. Build the Rust FFI library

#### macOS

```bash
# From the repository root
cargo build --release -p toku-ffi

# The static library will be at:
# target/release/libtoku_ffi.a
```

#### iOS

```bash
# Device binary
cargo build --release -p toku-ffi --target aarch64-apple-ios

# Simulator binary (Apple Silicon)
cargo build --release -p toku-ffi --target aarch64-apple-ios-sim

# The static libraries will be at:
# target/aarch64-apple-ios/release/libtoku_ffi.a
# target/aarch64-apple-ios-sim/release/libtoku_ffi.a
```

#### watchOS

```bash
# Device binary
cargo build --release -p toku-ffi --target aarch64-apple-watchos

# Simulator binary (Apple Silicon)
cargo build --release -p toku-ffi --target aarch64-apple-watchos-sim

# The static libraries will be at:
# target/aarch64-apple-watchos/release/libtoku_ffi.a
# target/aarch64-apple-watchos-sim/release/libtoku_ffi.a
```

> Tip: `./build-ffi.sh` (in `toku-apple/`) builds all iOS + watchOS device and
> simulator slices in one step and copies the generated header into `TokuKit`.

#### Building and running the watch app

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml` (it is not checked in). After building the FFI libraries:

```bash
cd toku-apple
xcodegen generate
xcodebuild -project Toku.xcodeproj -scheme TokuWatch \
  -destination 'platform=watchOS Simulator,name=Apple Watch Series 11 (46mm)' \
  -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

Or open `Toku.xcodeproj` in Xcode, select the **TokuWatch** scheme and a watch
simulator, and run (⌘R).

### 2. Copy the header

The header is auto-generated during build. Copy it to the Swift package:

```bash
cp crates/toku-ffi/toku.h toku-apple/TokuKit/Sources/CTokuFFI/toku.h
```

### 3. Generate the Xcode project

All targets — **TokuMac** (macOS), **TokuiOS** (iOS), **TokuWatch** (watchOS),
and **TokuWatchComplication** (WidgetKit) — are declared in `project.yml` and
generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen). You do **not**
create targets by hand anymore:

```bash
cd toku-apple
xcodegen generate            # writes Toku.xcodeproj (gitignored)
open Toku.xcodeproj          # or build a scheme from the CLI, below
```

Build any target from the command line (unsigned simulator/host builds need no
Apple account):

```bash
# macOS host app
xcodebuild -project Toku.xcodeproj -scheme TokuMac \
  -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build

# iOS app
xcodebuild -project Toku.xcodeproj -scheme TokuiOS \
  -destination 'platform=iOS Simulator,name=iPhone 16' \
  CODE_SIGNING_ALLOWED=NO build

# watch app (embeds the complication)
xcodebuild -project Toku.xcodeproj -scheme TokuWatch \
  -destination 'platform=watchOS Simulator,name=Apple Watch Series 11 (46mm)' \
  CODE_SIGNING_ALLOWED=NO build
```

CI builds all three of these in the `apple` job (`.github/workflows/validate.yml`).

#### App Group entitlement (device only)

The iOS app, watch app, and complication ship `.entitlements` files declaring
the `group.com.kafkade.toku` App Group (wired via `CODE_SIGN_ENTITLEMENTS` in
`project.yml`). This lets the complication read the live `WatchSnapshot` written
by the watch app instead of showing a placeholder. It is only enforced for
**signed device builds** — unsigned simulator/CI builds ignore entitlements and
fall back to standard `UserDefaults`, so they keep working with no signing team.

#### Beta distribution (TestFlight)

`.github/workflows/testflight.yml` archives, signs, and uploads the iOS app
(with the embedded watch app + complication) to TestFlight. It is a **scaffold**:
every signing step is guarded on secret presence, so it is a safe no-op until the
maintainer configures the signing secrets documented at the top of that file
(certificate, provisioning profiles, App Store Connect API key, team id). It runs
on `v*` tags or via **workflow_dispatch**. It is a delivery workflow, not a merge
gate, so branch protection (`kafkade/github-infra`, `repo_toku.tf`) is unchanged.

## Known limitations

### FFI gaps (to be addressed)

- **ISBN-based book addition**: The barcode scanner captures ISBN-13 codes but
  the current `toku_add_book` FFI function only accepts title/author. An
  ISBN-aware add function or metadata fetch through `toku-meta` FFI is needed.

### What cannot be validated on Windows

- Swift compilation and Xcode project setup
- Linking against `libtoku_ffi.a` (any platform)
- SwiftUI rendering and interaction
- macOS-specific APIs (NSOpenPanel, drag-and-drop)
- iOS-specific APIs (AVFoundation barcode scanning, UIDocumentPicker)
- iOS simulator and device testing

All Rust FFI code is validated by the `toku-ffi` test suite which runs on all
platforms in CI.
